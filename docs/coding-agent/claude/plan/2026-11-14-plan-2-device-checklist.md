# Rokid-Coder Plan 2 and Plan 4: device checklist

Everything here is a check that the overnight build could not do: it had no phone, no glasses and no `adb install` (R25). Each unit-tested behaviour is listed only where a device is the missing piece. Tick a box when the step is done and the result matches. Plan 4 (transport, pairing, alerts and voice) adds its own section at the end; where a Plan 4 item contradicts an older one, Plan 4 wins.

**Setup for all checks**
- Android phone with the Plan 2 Agents APK and the fork `phone-hub`; Rokid glasses with the fork `glasses-hub` (the Task 11 hold and the Task 12 ack need it). Install over adb in the morning.
- A computer running the Plan 2 `agentd` (with the Task 10 client certificate), paired with a pairing line that carries `fp` and `steer`. Unless an item says otherwise, the link is secure (TLS) and Monitoring is on.
- A Claude session attached with `/rokid:on` and, where an item says so, one Codex session attached with `rokid:on`.
- Item sources use the ledger's ruling numbers (R..) and task numbers (T..) from `.superpowers/sdd/2026-11-14-plan-2-phone-glasses/progress.md` and the Plan 1 ledger.

## Known interim behaviour (read first)

- **R47: until Task 13, an untouched band never gets spoken reminders.** The glasses `TIMEOUT` close is not display evidence, because it can fire for a band that was never attached (R42 was withdrawn). Until the phone-hub forwards `/notice/shown` (Task 13), the only evidence that a band was seen is a tap on it (`/notice/action`), glasses input on it (`/notice/input`), or a wearer-originated close (`USER`). A band nobody touches stays "unconfirmed": agentd retries it silently, with a bounded number of wakes, and never reaches the spoken reminder. This is a temporary exception to design section 12.2 (R33). It is expected, not a bug, until item "End-to-end shown ack" passes. **Plan 4 (U1): reminders are now silent, so the "spoken reminder" half of this no longer exists.** What is left of R47 is whether an untouched band counts as seen, which still decides retries and wakes.
- **R33:** Task 13 (phone-hub routing of `/notice/shown`) is deferred because `../CxrGlobal` is absent. No phone advertises the plugin-facing ack bit, so the glasses never send the ack today.
- **R40 (superseded by Plan 4, U8):** there is no monitor-only or plaintext link any more. A phone paired without a client certificate, or over `ws`, is refused and shown "Pair again". The "Monitor only — approve on laptop" text is gone. Ignore the monitor-only wording in older items below; the Plan 4 section replaces them.
- **R39:** swipe-through of queued alerts is deferred; the band shows only "+N waiting".
- **R121:** the phone trusts a new machine only inside the wearer-armed two-minute window (Add a computer → Open the door), the first computer included. No computer links on first use. Open the door before every first link below.

## TLS and pairing

- [ ] **DIGEST_NONE keystore signing under Conscrypt.** Steps: open Settings and read "This phone's fingerprint", then link agentd to the phone. Expected: the handshake completes and agentd logs `phone_link_pinned` with the same 16 hex digits as the settings row. - [ ] **Conscrypt client auth.** Steps: with the phone as the TLS server, let agentd (Node client, which presents its own certificate) dial in. Expected: the phone requests and receives the client certificate even though the server sends an empty CA list, and the link goes secure; the first connect inside the open door pins agentd's certificate per computer. With the door closed, a computer the phone does not know is refused (`unknown_machine`), even when no computer is linked yet. From: R114, R120, R121, T10 re-review.
- [ ] **Pin persistence.** Steps: after a secure link, force-stop Agents and restart it; restart agentd; reboot the phone. Expected: the link returns secure each time with no re-pairing, and `agentd phones list` still shows the phone's fingerprint. From: R38, T10.
- [ ] **Pin rejection, outbound.** Steps: edit one character of `fp` in the pairing line and paste it. Expected: "Computer's certificate changed — re-pair", final (no retry loop), no token or `steer` sent, no fall back to `ws`. If the screen shows "Secure link failed" instead, `PinMismatchException` did not survive Conscrypt's cause chain: it still fails closed, but note it. Then paste the correct line: the client restarts. From: R38, R113, T10 review.
- [ ] **Pin rejection, inbound.** Steps: with the phone linked and pinned, stop agentd and delete its tls directory (this is the factory reset: agentd gets a new certificate and trusts no phone). Expected: only now does the phone refuse, before `hello_ack`, with "Computer's certificate changed — re-pair". Without the `allow-next` step agentd refuses the phone first and the phone-side message never appears. Forget the computer on the phone and pair it again to restore the link. A computer that presents no client certificate (older agentd) cannot link at all. From: R114, R120, T10 fix round.
- [ ] **AUTH_FAILED text.** Steps: trigger the refusal above and look at the link line in Settings and in Add a computer. Expected: the detail text is rendered, not blank. From: T10 review (c).
- [ ] **A second phone and `allow-next`.** Steps: with one phone trusted, try a second phone; then run `agentd phones allow-next` (or `agentd pair`) and try again within two minutes. Expected: refused outside the window, trusted inside it, and agentd refuses plaintext dials once a phone is trusted. `agentd phones forget <fp>` drops its link. From: R45, R112, T10.
- [ ] **Old or malformed pairing lines (replaces the monitor-only check).** Steps: paste a line that has no `fp`, then one with `fp` but no `steer`, then one with a malformed `steer`. - [ ] **Steering secret rotation.** Steps: run `agentd pair --rotate-steer` with the phone linked. Expected: agentd sends `link_trust` with `steering: false`, then closes the link (4403).
