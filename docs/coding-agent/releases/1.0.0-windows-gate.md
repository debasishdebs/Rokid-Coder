## Tools

- **netprobe.** In WSL: `~/.rokid-coder/bin/rokid-node <path>/gate/netprobe.mjs`. On the Mac: `node computer/installer/windows/gate/netprobe.mjs`. Its modes are:
  - `listen-tls --port <p> --cert <pem> --key <pem>`: prints the fingerprint of the cert it was given
  - `dial-tls --host <h> --port <p>`: prints the peer's fingerprint
  - `listen-udp --port <p>`
  - `send-udp --broadcast --port <p>`

  It prints no secrets.
- **agentd's fingerprint, in WSL:** `openssl x509 -in ~/.rokid-coder/tls/agentd.crt -noout -fingerprint -sha256`, or `agentd pair`. The pairing line shows only a short form.
- **What setup recorded:**
  - in Windows: `%LOCALAPPDATA%\RokidCoder\binding-<gen>.json` and `%ProgramData%\RokidCoder\machine-state.json`
  - in WSL: `~/.rokid-coder/install.json` and `~/.rokid-coder/logs/setup.log`

## Questions the gate answers for the fix wave

- **W1:** Can a standard user register the AtLogOn task (`\RokidCoder\agentd`), or does the HKCU `Run` value ship (`autostart.kind: run-key`)?
- **W2:** Is `conhost.exe --headless` really windowless at logon?
- **W3:** Are both firewall layers (host and Hyper-V) needed? Does the Hyper-V cmdlet take `LocalSubnet`? (`$HyperVTakesLocalSubnet` in `lib/RokidCoder.psm1`.)
- **W3/W7:** Which host process owns a WSL listener in mirrored mode? `wsl.ts` and the preflight ignore `wslrelay.exe`, `wslhost.exe`, `vmmem`, `vmmemWSL` and `vmwp.exe` as relays.
- **W7:** Does `powershell.exe -Command <script>` read its JSON from stdin through interop? This is how every fixed script in `wsl.ts` takes its data. CI's `legacy_windows_daemon_stopped_by_exact_identity_and_ports_verified` proves it only from Windows itself.
- **All:** Is the Windows drive at `/mnt/c`? `wsl.ts` assumes `/mnt/c/Windows/System32` (an `automount.root` other than `/mnt` is not handled).
