1. **[Important] The move/keep map leaves core code dependent on shell state.** ADR §2.1 keeps `hubEnabled` in the shell, but the supposedly verbatim SPP code reads it at `BusHubService.kt:337,3610,3621,3830,3853,3872`. Likewise, §2.3 moves `revokePrincipal`/`authorizationChanged` into core, although `:2627-2651` references shell controllers, grant stores and skills. **Fix:** keep an authoritative enabled gate in core, synchronized by shell lifecycle; explicitly split revocation side effects into shell hooks. Preserve the SPP identity/enrollment checks and byte-identical auth files.

2. **[Important] Pending speech cancellation is not specified sufficiently to deliver S7.** ADR promises `SpeechHandle.stop()` ends its run, but reused `NexusSpeechSession.stop()` returns immediately while `PENDING` (`NexusSpeechSession.kt:82-88`). Agents currently compensates by stopping after acceptance (`VoiceCapture.kt:49-52`). Also, active `stop()` invokes the terminal callback synchronously, contradicting “any-thread calls, main-thread callbacks.” **Fix:** define cancellation latching through acceptance and main-thread serialization, with tests for stop-before-acceptance and background-thread stop.

3. **[Important] Attach/detach and restart need an explicit lifecycle contract.** ADR L8 promises no callbacks after detach and cancellation of outstanding work, while §3.3 merely describes transport closure. `NexusPluginClient.close()` terminates speech with `ERROR` and TTS with `UNAVAILABLE` (`:1001-1024`), unlike the promised cancellation reasons; closed clients cannot reconnect. Queued callbacks can also outlive listener replacement. **Fix:** specify release-before-close, listener-generation invalidation, client recreation, initial state delivery, and whether detach hides notices/surfaces and closes foreground ownership.

4. **[Important] Installer cancellation does not yet protect the shared CXR callback slot.** ADR §3.6 says cancellation after upload is ignored, but coroutine cancellation ordinarily unwinds `finally`, deleting the copy and releasing the slot before CXR completes. Existing `uploadYoutubeApk` deliberately retains ownership until callback/disconnection (`BusHubService.kt:4602-4611`). **Fix:** define operation-scoped cancellation, non-cancellable post-dispatch ownership, callback generation checks, progress threading, and cleanup on exceptions/disconnection. Apply the same arbiter to `installedVersion()` queries, launches and third-party uploads.

5. **[Important] CI would stop exercising moved suites.** ADR §6 moves tests into the cores; Open point 2 says T2 does not update workflows. Both `tests.yml:78-79` and `upstream-validation.yml:64-65` currently invoke only hub test tasks. **Fix:** include both core suites in both workflows as part of this split, with the stated union-parity check.

6. **[Minor] The shell boundary still leaves signatures and execution rules to inference.** ADR §3.5 lists many `HubCore` members by name only, and provides no hook threading/reentrancy contract. For example, shell-only `authorizationChanged` effects need ordering relative to registration removal and capability notifications. **Fix:** give complete signatures and thread/ordering rules for every cross-module entry point; replace the already-decided factory/version/rename alternatives in §7 with the controller’s rulings.
