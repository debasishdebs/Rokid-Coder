**Verdict: not ready.**

1. **Critical — Task 4, idle gate (lines 249–254).** “Last hook was Stop” becomes eligible immediately after `StopWait.deliver`, although Claude is continuing the supplied prompt. SessionStart also doesn’t prove readiness, and quiet output doesn’t prove inactivity. **Fix:** define an explicit busy/held/idle state machine, distinguish Stop release reasons, mark delivered follow-ups busy synchronously, and require positive prompt readiness. Test silent busy periods and consecutive follow-ups.

2. **Critical — Task 1, binding (lines 118–135).** Exact IDs prevent cwd confusion but don’t establish ownership. A client can register its own launcher ID and submit an HTTP hook claiming another session’s ID; UUID validation authenticates nothing. Duplicate launcher IDs and competing session owners are unspecified. **Fix:** define authenticated launcher registration **and proof that the session belongs to its launched child**; enforce provider matching and exclusive ownership. Strip body-supplied launcher metadata. Test forged headers/env, victim session IDs, duplicate hello, and ownership collisions.

3. **Important — Tasks 3–4, delayed dispatch (lines 206, 227, 249–254).** The daemon checks eligibility before dispatch, but Typist can wait another 60 seconds. During that interval, Claude can become busy, a hook can open, or the session can detach/rebind. **Fix:** bind commands to a session/binding generation, support cancellation, and revalidate readiness immediately before each write. Test these transitions while a command waits.

4. **Important — Task 3, laptop input (lines 206–215).** A user can pause for 1.5 seconds with unfinished text in the prompt; the launcher then appends `/compact` or a reply. During `/model`, explicitly letting human keystrokes pass while automation finishes permits interleaved dialog actions. **Fix:** require an empty prompt and define exclusive input ownership during automated commands, including safe laptop takeover. Test partial drafts, pasted input, and user interaction during confirmation.

5. **Important — Tasks 2/4, compact completion (lines 178, 208, 247).** The fake emits PostCompact, but the existing Claude plugin’s `hooks.json` doesn’t register it. Real completion can therefore time out while tests pass. **Fix:** add the required real hook registrations and correlate completion with the active session, binding generation, and compact operation. Keep serialization through completion; test the actual bundled plugin configuration.

6. **Important — Architecture, Task 2 and Task 5 (lines 166, 297).** Codex’s shared daemon may execute hooks outside the launcher’s inherited environment. Existing evidence establishes hook session IDs, not propagation of `ROKID_LAUNCHER_ID` from each TUI through that daemon. The plugin currently registers only UserPromptSubmit, so startup attachment is also unproven. **Fix:** make per-TUI environment propagation and startup identification a prerequisite experiment, with two concurrent launchers. If unavailable, specify another exact-ID handshake. Deferred smoke cannot justify marking this delivered.

7. **Important — Task 1, lifecycle (lines 135–136), Task 4 decoration.** Binding on every hook can undo `/rokid:off`; a late old-session hook can reverse a rebind. Persisted launcher mode also survives daemon restart without a live launcher. **Fix:** specify explicit-detach suppression, authorized session transitions, retired bindings, pending-command cancellation, and startup reconciliation. Advertise launcher capabilities only with a current live binding. Add detach, late-hook, restart, and rebind tests.

8. **Important — Global socket contract; Task 1 (line 137).** File modes alone leave startup and protocol behavior underspecified: existing directory ownership/modes, symlinks or non-socket paths, probe errors, duplicate connections, malformed/oversized frames, and forged command results. **Fix:** define fail-closed filesystem checks, unlink only demonstrably stale owned sockets, strict bounded frame parsing, handshake deadlines, and result correlation to the originating connection and command. Test each rejection.

9. **Important — Task 2, terminal cleanup (lines 165–175).** Raw-mode-off plus cursor-show doesn’t restore the prior terminal state or define child cleanup. Signal termination, spawn failure, stdin EOF, and background/suspend handling remain implementer decisions. **Fix:** specify saved-state restoration, signal forwarding, child/process-group termination and reaping, and exit-status mapping. Verify terminal flags on the same PTY after exit and verify no child remains.

10. **Important — Task 3, model recovery/tests (lines 207–225).** Matching generic output strings can accept stale or unrelated text; ANSI sequences and markers can span chunks. Writing Esc/Ctrl-U proves only bytes were sent, not that the prompt was cleared or the dialog dismissed. **Fix:** use command-scoped incremental parsing, bounded buffers, and explicit confirmation/recovery states. Extend the fake to model editable prompt/dialog behavior, and assert final state under chunk splitting, misleading output, timeout, and laptop takeover. Preserve the ban on live `/model` tests.
