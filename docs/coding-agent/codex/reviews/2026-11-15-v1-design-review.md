VERDICT: NOT READY

1. **[Critical] Automatic pairing does not authenticate the intended peer.** §8.1 automatically pins whichever peer connects during each window and removes fingerprint comparison. Existing outbound pairing explicitly asks users to compare fingerprints (`agentd/src/cli.ts:139`); admission otherwise permits first use during a window (`agentd/src/phone-link.ts:655`). Encryption alone cannot prevent pairing with a nearby attacker. **Change:** require a QR-bound exchange or explicit matching verification on both devices before granting steering access; define cancellation, expiry and competing-peer behavior.

2. **[Important] The single-app integration boundary is unspecified.** Agents extends `NexusPluginService` (`plugins/agents/src/main/java/com/anezium/rokidbus/plugin/agents/AgentsPluginService.kt:44`), while the SDK targets the old hub package (`bus-client/src/main/java/com/anezium/rokidbus/client/HubTarget.kt:17`). §3.1 removes the host without choosing its replacement. **Change:** select a private internal adapter or private same-app service path, defining how surfaces, input, speech, notices and lifecycle work without external discovery or plugin grants.

3. **[Important] Excluding Gradle modules cannot remove the store, updater or plugin host.** These live inside `phone-hub`: its manifest exports `BusHubService`, declares store activities and exposes the Patcher entry (`phone-hub/src/main/AndroidManifest.xml:62–96,175–182`); discovery queries installed plugin services (`PhonePluginDiscovery.kt:74–85`). **Change:** specify a product variant/library split that excludes their code, manifest entries and startup paths. Require inspection of the release manifest and rejection tests using an unrelated app.

4. **[Important] U34 leaves the Windows release architecture undecided.** §9 defers daemon location, hooks and installer contents, while §8.3 promises Windows Node/node-pty artifacts. A daemon inside WSL needs Linux binaries and Unix sockets; a Windows daemon needs cross-boundary integration with WSL hooks and Codex’s socket. **Change:** settle the execution environment, supported distro/WSL versions, runtime artifacts, state ownership and login startup before planning. Explicitly reconcile the older named-pipe/ConPTY work list in `HANDOFF.md:60–66`.

5. **[Important] The WSL networking question reverses the existing connection direction.** §9 asks how phone TLS dial-in reaches WSL, but `agentd` broadcasts and then dials the phone (`agentd/src/phone-link.ts:43–51`). Tailscale discovery invokes a local executable (`agentd/src/tailnet-discovery.ts:64–80`), which also needs a defined location under WSL. **Change:** document directions and ports for discovery, TLS and hooks; choose a fallback for blocked broadcasts and define host-versus-WSL Tailscale ownership. Mirrored networking has Windows-version and firewall prerequisites; it is not an unconditional installer setting. [Microsoft documentation](https://learn.microsoft.com/windows/wsl/networking)

6. **[Important] Bundled Node does not make existing hooks work without system Node.** Hook commands invoke bare `node` (`plugins/claude-code/hooks/hooks.json:8`); launchd setup also resolves it from PATH (`agentd/scripts/install-launchagent.sh:21–26`). **Change:** define stable runtime wrappers used by hooks, `rk` and autostart, plus the pinned Node version and matching native artifacts. Gate installers on clean machines without Node or build tools, including paths containing spaces and non-ASCII characters.

7. **[Important] The subtree restructuring lacks a preservation map.** §8.8 adds upstream `main`, while current Agents is a separate Gradle build pointing back to root modules (`plugins/agents/settings.gradle.kts:21–28`), and both hubs are application modules. Moving upstream beneath `vendor/nexus` also changes the meaning of its relative CxrGlobal path (`settings.gradle.kts`, `cxrGlobalDirectory`). **Change:** identify the exact upstream SHA, where current release code and patches land, which build owns each module, and how root-relative scripts/dependencies resolve. Require behavior parity after restructuring before feature work.

8. **[Important] Bundling the glasses APK needs a defined replacement for release discovery and verification.** Current installation resolves a GitHub release, downloads its APK, verifies package/version/digest/signer, then calls CXR (`phone-hub/src/main/java/com/anezium/rokidbus/phone/BusHubService.kt:4388–4455`). Renaming also affects hard-coded package and component names (`:150,3978,4020`). **Change:** specify bundled metadata, preserve verification before every push, distinguish application IDs from class namespaces, and define already-installed/newer-version, retry and update behavior.

9. **[Important] “Bundled APK means Play-compatible” is unsupported.** §§6/8 treat bundling as the solution, but Google restricts APK bundling under `REQUEST_INSTALL_PACKAGES` except qualifying device-management purposes. The existing CXR call delegates installation; the cited path does not establish that the phone needs that permission. **Change:** determine and document the actual permission requirement, remove the permission if unnecessary, and make the Play distribution strategy a separate unresolved decision rather than a guaranteed property. [Google Play policy](https://support.google.com/googleplay/android-developer/answer/18265346)

10. **[Important] Background monitoring and microphone ownership remain undefined after merging.** Agents uses `specialUse` foreground services and a battery exemption (`plugins/agents/src/main/AndroidManifest.xml:14–25,70–85`); the hub declares `connectedDevice|microphone` and a boot receiver (`phone-hub/src/main/AndroidManifest.xml:175–195`). **Change:** choose the merged service lifecycle and foreground-service types, including reboot, background voice requests, denied permissions and user Stop. Android restricts background and boot starts involving microphone services. [Android documentation](https://developer.android.com/develop/background-work/services/fgs/service-types)

11. **[Important] “Done” can pass without proving the product works.** §3 mainly lists packaging; §2 ends at a sessions board despite supporting users with neither CLI and without specifying session attachment. Earlier design §3 contains substantive behavior and safety requirements, while `HANDOFF.md:20` records unfinished device and Codex checks. **Change:** explicitly carry forward the applicable behavior contract and gate release on both tools: attachment, approvals, questions, same-session replies, timely alerts, DND, disconnect/reconnect, expiry/revocation and launcher typing safety. Add installer upgrade/uninstall and onboarding recovery criteria.

12. **[Important] The privacy promise is broader than the architecture supports.** §3.10 says no data leaves devices and there are no servers, while Claude/Codex use external providers and §8 supports Tailscale. Nexus also retains configurable cloud speech engines (`phone-hub/src/main/java/com/anezium/rokidbus/phone/SpeechSettingsActivity.kt:271–279`). **Change:** distinguish Rokid-Coder-operated services from vendor services; choose whether cloud speech is excluded and disclose the actual data paths.

13. **[Minor] The transport anti-goal conflicts with existing local exceptions.** §5 prohibits *any* unencrypted link, but U9 accepts loopback hooks, which use HTTP (`agentd/src/hook-forward.ts:3`). UDP discovery is also plaintext. **Change:** scope pinned TLS to computer–phone application traffic on both paths, explicitly preserve the local-hook/discovery exceptions, and separately state the required CXR/SPP protections.
